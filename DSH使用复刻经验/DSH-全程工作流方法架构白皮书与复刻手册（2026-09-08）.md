# 全程工作流方法 · 架构白皮书与复刻手册

> **版本**：v1.0（2026-09-08 定稿）
> **目标读者**：未来的你（换电脑/重装系统/DSH 升级后），或任何要在新环境复刻这套方法的人
> **一句话**：让 DSH 会话里的 AI——**不管换什么模型**——都按"开始→经过→结果"三步法工作流干活，规矩全程在线、不依赖模型自觉调用。
> **本文地位**：这套方法的完整架构说明 + 从零复刻操作手册。复刻所需全部素材已在 git 仓库内（见「复刻资产清单」）。

---

## 一、这套方法解决什么问题

**原始痛点**：服务中心有一套精心设计的工作流（三步法检查点 + 3k/xf/gd 质量闭环技能），但它们躺在技能目录里**靠模型自觉调用**——模型不听话时直接跳过，导致：

- 该跑 3k 验货的不跑就报"完成"
- 该调工具的用叙述蒙混
- 走偏了没人拉回来
- 换个弱模型，规矩全丢

**解法核心**：把规矩从"技能目录（要调用才生效）"搬到"**全程在线通道（首请求自动注入，每个步骤都在场）**"。模型不需要"想起来"去调用什么——规矩从会话第一步就贴在它眼前，直到结束。

**验证状态**：v1.0 落地后首战实测通过（2026-09-08 统计函数库交付：ponytail 极简 → 3k 验货 97 分 → 闭环四件套全齐，全程无人工催促）。

## 二、总体架构：三层规则体系

```
┌──────────────────────────────────────────────────────────────┐
│ 第一层：README.md（中心章程 · 权威层）                          │
│ 位置：D:\DSH-服务中心\README.md                                │
│ 内容：环境网络事实 / 九条铁律 / 目录规则 / 技能清单 / 历史记录    │
│ 冲突时以它为准（三层中唯一权威源）                               │
└──────────────┬───────────────────────────────────────────────┘
               ↓ 由 persona 摘要注入（防遗忘）
┌──────────────────────────────────────────────────────────────┐
│ 第二层：persona（服务模式预设 · 摘要层）                        │
│ 位置：~\.dsh\.agent-presets\service\agent.cordis.yml           │
│ 机制：DSH 预设系统，会话启动即渲染注入系统提示，随请求携带        │
│ 内容：章程摘要 + 环境事实速查 + 3k/xf/gd 强制协议 + 三步法摘要   │
└──────────────┬───────────────────────────────────────────────┘
               ↓ 指向完整版
┌──────────────────────────────────────────────────────────────┐
│ 第三层：AGENTS.md（全程在线指令 · 工作流权威层）★核心创新        │
│ 位置：D:\DSH-服务中心\AGENTS.md                                │
│ 机制：DSH 内置 dsh-agent-instructions 插件自动加载              │
│ 内容：三步法检查点完整版 + 技能调用纪律 + 走偏纠正规则表          │
└──────────────────────────────────────────────────────────────┘

配套引擎：技能库（D:\DSH-服务中心\技能\）
  3k（单核三拷问·交付前质量门禁）→ xf（修复）→ 3k 复检 → gd（归档）
  由第三层的"技能调用纪律"强制触发，由第二层的 MANDATORY 协议兜底
```

**分层逻辑**（为什么是三层而不是一层）：
- README 是"宪法"——太长（约 4.5 万字节），不可能全文注入每个请求；
- persona 是"摘要卡片"——会话启动带上，防环境事实遗忘，但预算有限只放精华；
- AGENTS.md 是"岗位操作规程"——工作流的完整权威版，恰好够小（3.8KB，占预算 5.8%）可以全程注入；
- 三者冲突时以 README 铁律为准（AGENTS.md 文件头明确声明了这一点，防止双源漂移）。

## 三、逐层明细

### 第一层：README.md 章程

| 项 | 内容 |
|:---|:---|
| 是什么 | 中心唯一权威章程：环境网络事实（第 0 节）+ 九条铁律 + 目录结构 + 技能清单表 + 历史记录 |
| 在哪 | `D:\DSH-服务中心\README.md`（git 仓库根） |
| 怎么工作 | 不直接注入模型；通过 persona 摘要 + AGENTS.md 速查引用它；会话启动协议要求先读第 0 节 |
| 维护规则 | 铁律 5：任何目录/规则调整当场同步更新本文件（"活地图"） |

**九条铁律速览**（完整版见 README）：①唯一存放地 ②技能唯一路径 ③文档归档 ④新增目录先登记 ⑤随手同步 ⑥语言纪律（简体中文） ⑦交付即闭环（生命周期+入库+沉淀+无残留） ⑧失败即换思路（连败2次停） ⑨交付先三拷问（3k）。

### 第二层：persona 服务模式预设

**这是复刻断点之一——此文件不在 git 仓库内，必须单独落位！**（已备份：`文档\复刻资产备份\agent.cordis.yml` + `preset.yml`）

**结构**（agent.cordis.yml，约 300 行，cordis 预设组合文件）：

| 段落 | 作用 |
|:---|:---|
| `id: persona` | 会话人设：服务代理身份 + 中心章程摘要 + 环境网络事实（代理 10808/GitHub/web_search 兜底）+ 3k/xf/gd MANDATORY 协议 + 语言纪律 + **全程工作流纪律三步法摘要（指向 AGENTS.md）** |
| `id: agent-instructions` | 指令预算 maxBytes: 65536（AGENTS.md 加载器） |
| `id: tool-pwsh` / `tool-bash` | Shell 工具（按平台自动启停） |
| `id: tool-fs` / `tool-fs-search` / `tool-jobs` | 文件/搜索/后台任务工具 |
| `id: skill-filesystem` | **技能目录挂载**：`customSkillDirs: ["D:/DSH-服务中心/技能"]`——中心 11 个技能由此进入会话 |
| `id: tool-skill` | 模型可调用的技能加载工具 |
| `id: compaction`（group） | 会话压缩三件套：compaction-basic（自动压缩）+ command-compact（手动命令）+ tool-result-pruner（工具结果修剪，threshold 8192/head 4096/tail 1024——省 token 引擎） |
| `id: delegation`（group） | subagent/fork/ralph/workflow 委托工具组 |
| `id: mcp-basic-memory` | basic-memory 长期记忆桥接 |
| 其余 | goal/plan-mode/todo/web/ask-user 等标准工具 |

**生效机制**：settings.yaml 里 `agent-presets: default: service` → 每个新会话自动挂载此预设 → persona 文本渲染进系统提示（`{{model}}`/`{{cwd}}` 变量随会话解析）。**修改即时生效，无需重启 DSH**（下次请求重新渲染）。

**preset.yml**（同目录，3 行）：预设名"服务模式" + 描述 + 排序。让预设出现在 DSH 预设选择器里。

### 第三层：AGENTS.md 全程在线指令 ★核心创新

| 项 | 内容 |
|:---|:---|
| 是什么 | 工作流的**权威完整版**，DSH 官方 `dsh-agent-instructions` 机制自动注入 |
| 在哪 | `D:\DSH-服务中心\AGENTS.md`（git 仓库根，随 clone 即得） |
| 怎么工作 | 见下方"技术原理" |
| 内容结构 | 使命 → 三步法检查点（开始3问/经过3问/结果3查）→ 技能调用纪律 → 走偏纠正规则表（5信号×纠正动作）→ 中心规则速查 |

**为什么它解决了原始痛点**：技能目录的机制是"模型看到清单 → 模型决定调用 → 加载全文"——三步都依赖模型自觉。AGENTS.md 的机制是"**首请求就注入 → 每个后续步骤都携带**"——零调用、零自觉依赖，换任何模型规矩都在场。

### 配套引擎：3k → xf → gd 技能闭环

| 技能 | 位置 | 职责 | 触发 |
|:---|:---|:---|:---|
| `3k` 单核三拷问 | `技能\单核三拷问\SKILL.md` | 交付前质量门禁：依赖/逻辑/路径拷问 + 闭环拷问，输出评分报告 | 任何交付物报完成前**强制**；触发词 3k/三拷问/验货/报完成；按任务形状触发（修复/排障收尾/方案落地） |
| `xf` 修复 | `技能\修复\SKILL.md` | 读 3k 不通过项，生成并应用最小修复补丁 | 3k 报告存在不通过项时 |
| `gd` 归档 | `技能\归档\SKILL.md` | 沉淀 3k→xf→3k 全过程入 jsonl | 值得归档的完整闭环跑 |

**报告落点**：`文档\3k_reports.jsonl` / `xf_log.jsonl` / `3k_log.jsonl`（逐行 JSON 追加，**只追加不覆盖**——历史教训：整文件 write 曾覆盖丢 131 条记录）。

**功能技能**（11 个，全部在 `技能\` 一层目录）：douyin 系 4 个（视频下载/主页批量/直播录制/文案AI）、closeai-model-bridge、e-commerce-poster-pipeline、ponytail（极简编码）、ui-design + 3k/xf/gd。技能目录格式：`技能\<中文展示名>\SKILL.md`，frontmatter `name` 为 kebab-case（平台硬校验），**只扫一层**。

## 四、技术原理（依赖的 DSH 机制）

### 4.1 dsh-agent-instructions（第三层的引擎）

- **内置插件**，dsh-base 默认包含，无需安装——只要工作区根有 `AGENTS.md` 就生效；
- 会话**第一次请求**自动加载为"持久基线消息"：先是全局 `~\.dsh\AGENTS.md`（若有），再按"宽泛→具体"顺序加载项目链（从 .git 根到 cwd 的每个目录的 AGENTS.md/CLAUDE.md）；
- **自动刷新**：成功的 read/write/edit 文件操作后，下一次请求自动带入变更（无需重启——2026-09-08 实测：AGENTS.md 刚写入，下一请求即出现注入）；
- **字节预算**：maxBytes 65536（service 预设配置），超出时"较宽泛的先丢弃，最具体的最后截断"并发出可见通知。当前 AGENTS.md 3804 字节 = 5.8%，余量充足。

### 4.2 预设系统（第二层的引擎）

- `~\.dsh\.agent-presets\<预设名>\` 目录：`preset.yml`（元信息）+ `agent.cordis.yml`（组合定义）；
- settings.yaml `agent-presets.default: service` 指定默认预设；
- persona 文本每次请求随 `{{model}}`/`{{cwd}}` 渲染——**改文件即时生效**（2026-09-08 实测：21:31 改完，当前会话同请求已带新版）。

### 4.3 技能系统（配套引擎）

- `skill-filesystem` 插件的 `customSkillDirs` 指向 `D:/DSH-服务中心/技能`；
- 技能经 `<available_skills>` 目录注入（摘要），模型调用 `skill` 工具加载全文；
- `/技能名` 手势（用户消息中的 `/3k`）也会触发注入（dsh-tool-skill 的 SKILL_GESTURE 机制）。

### 4.4 稳定性设计（为什么零风险）

- AGENTS.md 是**纯静态 md**，无代码、无运行时、无依赖——最坏情况是"内容写错字"，不存在"把 DSH 搞挂"；
- 全部走 DSH 内置官方机制（agent-instructions / 预设 / 技能目录），零自研插件运行时；
- 对比：曾尝试的 dsh-workflow-supervisor 插件方案 4 处 API 全错 + cordis-plugin-loader 对 apply 抛错上抛 = 重启事故风险，已毙掉卸载（详见第七节）。

## 五、从零复刻手册（换电脑 / 重装 / DSH 升级后照做）

### 5.0 前置条件清单

| 依赖 | 要求 | 备注 |
|:---|:---|:---|
| 操作系统 | Windows（当前 Windows Server/10/11 均可） | 路径全为 Windows 形态 |
| PowerShell 7 | `C:\Program Files\PowerShell\7\pwsh.exe` | DSH shell 工具用；无则装之 |
| Git | 任意近期版本 | 需配代理（见 5.2） |
| Python | 3.8+（当前 3.11.8） | 技能运行环境重建用 |
| DSH Desktop | 当前 0.1.2-rc.x | 官方安装包 |
| 网络 | GitHub 需走代理（本机 v2rayN/xray mixed 端口 10808） | 新机器按实际代理调整，全文检索键：`10808` |

### 5.1 第一步：克隆中心仓库（拿回全部资产）

```powershell
# 代理配置（新机器若无代理，先解决网络再继续）
git config --global http.pty false  # 无此项，仅示意：仓库级配置见下

git clone https://github.com/Dubaoyai/3k "D:\DSH-服务中心" -b dsh-3k
git -C "D:\DSH-服务中心" config http.proxy http://127.0.0.1:10808
git -C "D:\DSH-服务中心" config https.proxy http://127.0.0.1:10808
# push 偶发 TLS 失败时单次覆盖：
# git -c http.sslBackend=openssl -c http.version=HTTP/1.1 push origin dsh-3k
```

克隆完成后仓库自带：README 章程 / **AGENTS.md** / 全部 11 个技能 / 全部文档沉淀 / 复刻资产备份。

### 5.2 第二步：落位预设文件（复刻断点①——仓库外文件）

```powershell
# 创建预设目录并复制（备份已在仓库内：文档\复刻资产备份\）
New-Item -ItemType Directory -Path "$env:USERPROFILE\.dsh\.agent-presets\service" -Force
Copy-Item "D:\DSH-服务中心\文档\复刻资产备份\agent.cordis.yml" "$env:USERPROFILE\.dsh\.agent-presets\service\" -Force
Copy-Item "D:\DSH-服务中心\文档\复刻资产备份\preset.yml" "$env:USERPROFILE\.dsh\.agent-presets\service\" -Force
```

**⚠️ 落位后必查两处按新机修改**：
1. `agent.cordis.yml` 里 `customSkillDirs: ["D:/DSH-服务中心/技能"]`——若新机中心路径不同，改这里；
2. `mcp-basic-memory` 段的 `command: C:\Users\Administrator\.local\bin\basic-memory.exe`——新机若无 basic-memory，先装或**删除该段**（不装 basic-memory 不影响三层体系核心，只损失长期记忆）。

### 5.3 第三步：settings.yaml 关键配置（复刻断点②）

`~\.dsh\settings.yaml` 需含以下关键行（完整参考版已在 `文档\复刻资产备份\settings.yaml`，含 providers 清单；**注意该文件只有 apiKeyEnv 引用名，真实密钥永不入库**）：

```yaml
agent-presets:
  default: service          # ← 三层体系的总开关：默认走服务模式预设
agent-default-model:
  provider: opencode-bridge # 按新机实际 provider 调整
  model: big-pickle
shell:
  pwshPath: C:\Program Files\PowerShell\7\pwsh.exe
  cwd: D:\DSH-服务中心       # 会话默认工作目录
```

**凭据恢复**（复刻断点③）：真实 API key 在 `~\.dsh\.credentials.yaml` 的 `refs` 段（**绝不进 git**）。新机需手工重建：
- 结构：顶层只有 `version/refs/records` 三键白名单（写错顶层键 DSH 会重启失败——2026-09-07 事故）；
- 各 provider 的 key 值按 `settings.yaml` 里 apiKeyEnv 名逐个补（AGNES_API_KEY / BAI_API_KEY / OPENCODE_BRIDGE_API_KEY 等）。

### 5.4 第四步：验证链（每步有明确通过标准）

| # | 验证命令/操作 | 通过标准 |
|:---|:---|:---|
| 1 | `dsh --profile desktop --dump-config \| Select-String "skill-filesystem" -Context 0,3` | 出现 customSkillDirs 指向中心技能目录 |
| 2 | DSH Desktop 启动 → 新建会话（预设选"服务模式"或默认即它） | 会话正常启动，模型列表可选 |
| 3 | 新会话随便发一句话，观察模型行为 | 模型第一步按三步法（先对齐需求/预检）而非闷头干；回复是简体中文 |
| 4 | 派一个小交付任务（如"写个单行脚本"） | 交付前模型**自觉加载并执行 3k**，报告入 `文档\3k_reports.jsonl` |
| 5 | 检查注入：新会话首请求应带 AGENTS.md 基线 | 模型行为符合三步法 = 注入生效（最直接信号） |
| 6 | 编码类任务看风格 | 按 ponytail 极简（标准库优先/最短 diff） |

### 5.5 第五步：按需重建运行环境（git 忽略区，按 SKILL.md 重建）

这些目录不入库（.gitignore），需要时按各技能 SKILL.md「运行环境」段重建：
- `运行环境\douyin-skills\`（venv：python3.12 + requests/playwright/chromium）；
- `运行环境\ponytail\`（上游仓库，走代理 `git clone github.com/DietrichGebert/ponytail`）；
- `运行环境\opencode-zen-bridge\`（若用 opencode 模型桥）。

**不影响三层体系核心**——不重建只损失对应功能技能，三步法/3k 闭环照常工作。

### 5.6 复刻资产清单（仓库内自带 vs 需手工落位）

| 资产 | 位置 | 获取方式 |
|:---|:---|:---|
| AGENTS.md | 仓库根 | clone 即得 ✅ |
| README 章程 | 仓库根 | clone 即得 ✅ |
| 11 个技能 | `技能\` | clone 即得 ✅ |
| 全部文档沉淀 | `文档\` | clone 即得 ✅ |

## 六、升级与维护注意事项

| 场景 | 动作 |
|:---|:---|
| **改 AGENTS.md** | 直接编辑，**下一请求即时生效**（write 触发刷新）；重大修改前先备份；改动后按 5.4 表第 3/4 项回归验证 |
| **改预设 persona** | 直接编辑 `~\.dsh\.agent-presets\service\agent.cordis.yml`，即时生效；**改完同步刷新 `文档\复刻资产备份\` 里的备份**（否则备份过期） |
| **DSH 升级** | 三个机制（agent-instructions/预设/技能目录）均为官方稳定接口，升级后按 5.4 验证链全跑一遍；若 dsh-base 的 agent-instructions 配置结构变化，对照官方 README 调整预设里对应行 |
| **加新技能** | `技能\<中文展示名>\SKILL.md`（一层，name 为 kebab-case）；README 目录树+技能清单表登记；AGENTS.md 若需引用它，加进"技能调用纪律"段 |
| **新会话不走三步法** | 排查顺序：① settings.yaml `agent-presets.default` 是否 service → ② 预设文件是否在位（`~\.dsh\.agent-presets\service\`）→ ③ AGENTS.md 是否在仓库根 → ④ 模型是否太弱无视指令（此时考虑换模型，或将来补 agnes 监工插件） |

## 七、设计与踩坑史（为什么是这个方案）

按时间线，方便理解每个设计的"为什么"：

1. **最初尝试：预设 persona 写 MANDATORY 协议**（有效但不够）——指令很强，但弱模型仍会无视。痛点未根治。
2. **第二次尝试：dsh-workflow-supervisor 插件 + agnes-2.5-flash 监工**（毙掉）——想法是平台级硬约束 + 独立 AI 监督。开发后装机，**用户叫停要求全检**，源码逆向取证发现 4 处 API 全错（`ctx.tool` 不存在 / pre-step 不调 `next()` 截断官方技能目录注入链 / turn-stopping 返回值被忽略 / 消息注入须 createUserMessage）+ cordis-plugin-loader 对 apply 抛错上抛 = **重启即 DSH 起不来的真实风险**（与 credentials 事故同型路径）。全检当日卸载，零残留。
   - **核心教训**（已沉淀经验库踩坑 18）：自研 DSH 插件动手前必读同型官方插件 `lib/index.js` 真源码；README 只讲行为语义不讲可抄签名；**装机未验证 = 挂雷**。
3. **换道：AGENTS.md 官方通道**（最终方案）——用户问"有没有技能全程在线的"，核实 `dsh-agent-instructions` 是官方内置、自动注入、免调用的通道，且本机一直空转（文件不存在 = 机制在但没子弹）。落地 3.8KB 工作流权威版，**当场实证**：写入后下一请求即注入，零重启零风险。
4. **监工定位的澄清**：用户点破监工就是"走偏了指引回来 + 查有没有调技能，就这么点事"→ 第一版方案过度设计（评分门禁/自觉汇报/阻塞拦截全砍）。agnes 真监工（独立 AI 观察）需求真实但暂缓——先验证三层体系的软约束成色，不够再按正确 API 补做（教训与模板已存档：`文档\监督代理prompt模板-插件方案遗留-20260908.md`）。
5. **首战验证**（2026-09-08 统计函数库交付）：新体系下首个会话完整跑通 ponytail → 3k(97分) → 闭环四件套，全程无人工催促。**方法灵验的第一个实证样本**。
